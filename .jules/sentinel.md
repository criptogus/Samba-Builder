## 2026-10-14 - Prevent Command Injection and Ensure Cross-Platform Compatibility in Shell Executions
**Vulnerability:** The codebase executed shell commands (e.g., `npm`, `pnpm`) using Node's `child_process.spawn` with `shell: true`, which opens up vectors for command injection. When migrating to `shell: false`, cross-platform compatibility breaks due to Windows requiring `.cmd` extensions for `npm/pnpm` and POSIX systems missing shell built-ins like `command -v`.
**Learning:** `spawn` with `shell: false` expects actual executables on the system PATH. Windows does not implicitly resolve `.cmd` or `.bat` files in `spawn(..., { shell: false })`, while `command` is a bash built-in (not a binary) and fails with `ENOENT` on macOS/Linux.
**Prevention:** Always use `shell: false` with properly escaped array arguments to prevent injection. For cross-platform execution, explicitly map `.cmd` extensions on Windows (e.g., `executable += ".cmd"`) and replace POSIX shell built-ins with actual binaries (e.g., replace `command -v` with `which`).
